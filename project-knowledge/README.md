# Project Knowledge

This directory is the repository's fresh, durable knowledge layer. It grows through real work; it is not a prerequisite checklist.

Read only the files relevant to the current task:

- `PRODUCT.md` — product purpose, priority, users, and scope.
- `DOMAIN.md` — domain meanings, responsibilities, and boundaries.
- `ARCHITECTURE.md` — intended dependency and ownership principles.
- `TERMINOLOGY.md` — canonical terms and rejected ambiguities.
- `DECISIONS.md` — durable decisions and their consequences.
- `PROJECT_STRUCTURE.md` — verified locations and implementation relationships.

Use `OBSERVED`, `DOCUMENTED`, `DECIDED`, `INFERRED`, and `UNKNOWN` when provenance matters. Preserve disagreements between current evidence and intended direction rather than rewriting one to resemble the other.

Keep entries concise, dated when useful, and owned by one authoritative file. Do not duplicate `AGENTS.md` or turn these files into task logs.
